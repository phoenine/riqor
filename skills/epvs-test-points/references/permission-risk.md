# 权限与 Scope 风险

用于分析 ePVS 用户、角色、scope、区域可见性和权限相关变更。

## 两个权限维度

| 维度 | 作用 |
|---|---|
| Authorities / Roles | 用户角色，例如管理员、普通用户、本地管理员 |
| Scopes | 用户可访问的区域、产线、子区域等业务范围 |

这两个维度不要混淆。角色决定能力上限，scope 决定非全量用户的数据可见范围。

## 风险判断

- 管理员角色可能绕过 scope 检查；不要假设所有用户都受 scope 限制。
- 非管理员用户通常应受 scope 限制；重点验证列表、详情、配置、报表、下钻和数据接口。
- UI 权限树选择不等于后端最终保存结果；需要检查保存逻辑和后端实体约束。
- 父节点勾选、半选、子节点级联要结合组件行为和保存逻辑判断。
- scope 可能只保存某一层级节点，父级或产线级显示可能只是 UI 级联结果。

## 测试点设计

至少覆盖：

- 管理员与非管理员用户看到的数据范围差异。
- 修改 scope 后，列表、详情、图表和接口响应是否同步变化。
- 父级勾选、子级勾选、取消勾选、半选状态的保存结果。
- 无 scope、单 scope、多 scope、跨区域 scope。
- 权限变更后的重新登录、刷新、切换车间或切换上下文。

## 证据要求

- 前端：权限树、用户编辑页面、路由守卫、按钮/入口可见性。
- 后端：用户保存、scope 持久化、查询过滤、管理员豁免逻辑。
- 数据：scope 表、用户-scope 关联、区域/产线/子区域实体。

无法确认管理员是否绕过 scope 时，记录为 open question，不直接写入确定性预期。
