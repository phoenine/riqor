# Web 自动化模式

用于 ePVS Web/UI 自动化，尤其是 React SPA、主页、车间选择、班次选择、图表数据断言等场景。

## Page Object 边界

- 根配置、浏览器观测、失败截图等放在全局 fixture。
- 用例层 fixture 放在测试目录 fixture，不重复定义全局配置。
- PageObject 表达用户动作和页面状态。
- ComponentObject 表达页面内组件，如车间选择、班次选择、图表、树。
- 不把登录、选车间、选班次作为所有用例的隐式副作用；需要的用例显式声明。

## SPA 故事线

React SPA 常见路径：

```text
登录 -> 车间选择 modal -> 主页空状态 -> 结构树节点 -> 层级视图 -> Tab/图表/下钻
```

自动化结构应镜像用户故事线，而不是旧多 URL 页面结构。

## 车间选择

- 首次访问可能需要清理本地 store 后刷新，以触发车间选择。
- 车间和工厂列表可能异步加载；等待时不要只等任一按钮出现。
- 选中态应根据真实 DOM 状态判断，不依赖装饰性文本。
- 选车间后应验证主页上下文、结构树或当前车间文本。

## 班次选择

- 班次选择会影响全局 Home 状态，不适合所有 Home 测试默认执行。
- 切换 area/车间后，即使按钮文本残留，也必须按真实状态重新选择班次。
- 需要验证未选择班次或空状态的用例，不要使用已选班次 fixture。
- 弹窗 overlay 可能拦截普通 click；必要时在 PageObject 内封装可靠点击策略。

## 图表断言

- 不要只看 SVG、rect、path 数量；无业务数据时图表也可能渲染坐标轴。
- 优先断言图表文本或业务指标不包含 Loading/No shift selected，并包含真实业务数据。
- SVG 不是 HTMLElement，读取文本时使用 `textContent` 类方法，不假设 `innerText` 可用。
- 避免写死单个 area 的产线命名正则。

## 执行前检查

- 明确 base URL、账号、租户、车间、有效班次和测试数据。
- 确认 Playwright/pytest 环境可运行。
- 共享环境执行必须有用户确认。
- 执行结果记录截图、console/pageerror、trace 或报告路径。
