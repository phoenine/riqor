# 验收资产检查规则

用于检查 release acceptance 的 pages/cases/报告资产是否一致、可追溯、可执行。

## 检查范围

- pages 与 cases 是否按设计单元配对。
- pages 中的 TC/RISK/DATA ID 是否被 cases 备注覆盖。
- cases 是否引用了 pages 不存在的 ID。
- 每条 TC 是否包含优先级、外部 ID/同步状态、前置条件、步骤、预期结果、备注。
- 测试步骤数量是否与预期结果数量匹配或有合理说明。
- 源码证据路径是否存在、无通配符、非裸文件名、行号未越界。
- pages 是否混入执行期章节，如验收记录、发现问题、回归结论。

## 解析兼容

历史资产可能有两种字段格式：

```markdown
优先级：P1
```

以及：

```markdown
前置条件
1. ...
测试步骤
1. ...
预期结果
1. ...
备注
覆盖 M03-TC-01。
```

检查器和人工评审都要兼容两种格式，避免产生大量假阳性。

## 质量闸语义

- 检查发现 error 时，脚本退出码可以是 1；这是质量闸失败，不是脚本异常。
- 报告应写入 run 目录或对应报告 artifact，不直接污染 pages/cases。
- 检查结果要能回溯到具体文件、TC 编号和缺失字段。

## Agent 行为

- 修改 pages TC 编号后，必须同步更新 cases 引用。
- 不要为了通过检查删除风险或用例；应补证据、补引用或记录缺口。
- source evidence 必须来自 dev repo 的实际文件，不用知识库路径伪装源码证据。
