# 版本验收 pages/cases 规则

用于 release acceptance 中设计验收范围、pages、cases 和执行记录。

## pages 与 cases 边界

`pages/` 表示验收设计单元，承载业务目标、源码阅读、路径、风险、测试点和数据口径。

`cases/` 表示可执行详细用例，承载前置条件、步骤、预期结果和备注引用。

不要把执行期内容写进 pages 设计稿，例如：

- 验收记录。
- 发现问题。
- 回归结论。
- 临时执行备注。

这些内容应进入执行记录、问题清单或报告。

## pages 推荐结构

```markdown
## 基本信息
## 业务目标
## 源码阅读记录
## 核心路径（PATH）
## 代码风险点（RISK）
## 页面测试点（TC）
## 数据口径（DATA）
```

pages 中的 TC 是摘要，不写详细步骤。

## cases 规则

- 每个 cases 文件应引用对应 pages 的 TC/RISK/DATA 编号。
- 步骤必须是用户可执行或自动化可执行的业务路径。
- 预期结果必须可观察、可判断。
- 步骤和预期结果必须按索引对应。
- 修改 pages 测试点编号后，必须同步更新 cases 的备注引用。

## SPA 单页应用

当应用路由很少，但主页面通过层级树、Tab、下钻、弹窗、双层 viewport 组织复杂业务视图时，`pages/` 不是 URL 页面，而是验收设计单元。

推荐前缀：

| 前缀 | 含义 | 典型内容 |
|---|---|---|
| Mxx | Module，应用框架层/独立交互入口 | 登录、车间选择、主页框架 |
| Vxx | View，业务功能视图 | 产量、时间线、节拍、设备维保 |
| Dxx | Data，数据/状态/模型验收单元 | API 契约、状态缓存、实体模型 |

D 类 pages 可记录 API、store/cache、实体模型和数据口径风险；D 类 cases 只保留能通过真实业务路径观察或判断的用例。

## SPA 重点风险

- 跨层级复用视图的参数和数据粒度。
- Tab、缓存、view stack 和上下文切换是否串状态。
- 车间、area、line、station、asset 切换后的数据隔离。
- 基础版/专业版权限入口是否按源码实际行为工作。
- 快速连续点击、分屏、回溯和下钻状态机。
